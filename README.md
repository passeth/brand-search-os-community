# Brand Search OS Community

자신이 분석할 사이트를 등록하고 **사이트 진단 → AI 검색 관찰 → 경쟁사 비교 → 개선 과제 → 콘텐츠 작성 → 재측정**을 운영하는 한국어 전략 워크스페이스입니다.

이 저장소는 독립 설치용 공개 템플릿입니다. 실제 회사의 브랜드·고객·수집 기록·계정·배포 환경·기존 Git 이력은 포함하지 않습니다. 처음 설치하면 빈 워크스페이스로 시작합니다. 특정 사이트용 소스 수정 없이 **브랜드 추가**에서 분석 대상을 입력할 수 있습니다.

## 에이전트에게 맡기는 시작 프롬프트

아래 내용을 통째로 복사해 Codex 등 파일·터미널·브라우저 작업이 가능한 에이전트에게 보내세요. **분석할 사이트 한 줄만 본인 주소로 바꾸면 시작할 수 있습니다.** 이미 자신의 사본을 만들었다면 저장소 주소도 그 주소로 바꾸세요.

사이트 주소만으로 계정 접근권한이 생기지는 않습니다. GitHub·Supabase·Vercel·Google 로그인, 최초 관리자 등록, 권한 승인과 비용 결정은 진행 중 필요한 시점에 안내받게 됩니다. 에이전트에 도구나 계정 접근이 없다면 그 단계만 직접 수행하고 이어갈 수 있습니다.

```text
다음 저장소를 사용해 내가 지정한 사이트를 분석하는 Brand Search OS를 설치하고 설정해 줘.

저장소: https://github.com/passeth/brand-search-os-community
분석할 사이트: https://www.example.com

나는 설치 방법이나 SEO에 익숙하지 않아. 계획 설명에서 멈추지 말고, 가능한 작업은 직접 진행하고 내 조작이 필요한 단계만 정확한 화면·버튼·입력 항목으로 안내해 줘.

1. 저장소의 AGENTS.md, README.md, docs/SETUP.md, docs/USER-GUIDE.md, docs/AGENT-GUIDE.md를 먼저 읽고 현재 구현에 맞춰 진행해 줘. 설치 중 코드를 수정한다면 설치된 Next.js·AI SDK 문서도 확인해 줘.
2. 사용 가능한 도구와 계정 연결 상태를 먼저 확인해 줘. 이미 알려진 정보는 다시 묻지 말고, 저장소 소유 계정·프로젝트 선택·관리자 이메일처럼 꼭 필요한 미확정 정보만 묶어서 물어봐 줘. 접근이 막힌 단계가 있어도 독립적으로 진행할 수 있는 준비·검증·문서는 계속해 줘.
3. 원본 공유 저장소를 수정하지 말고 내 계정에 설치용 사본을 만들어 줘. 기본은 비공개 템플릿 사본으로 하고, 기존에 내가 만든 사본을 지정했다면 그것을 사용해 줘. 다른 사람의 운영 저장소·데이터·환경변수·Git 이력을 복사하지 마.
4. 내 설치용 Supabase와 Vercel 프로젝트를 준비하고, 의존성 설치, DB 마이그레이션, Auth 사용자와 seo_members 권한, 환경변수, 로컬 실행까지 설정해 줘. 기존 프로젝트를 재사용할 때는 대상과 기존 데이터를 확인하고 초기화하지 마. 최초 비밀번호 입력은 내가 직접 하도록 안내해 줘.
5. 도구 배포 주소(APP_URL)와 분석할 사이트를 구분해 줘. 분석 사이트는 소스 코드에 하드코딩하지 말고 브랜드 추가로 등록해 줘. 공개 사이트를 읽고 브랜드명·고객·키워드·경쟁사·질문 초안을 제안하되, 추정은 표시하고 경쟁사 후보는 내 확인을 받아 확정해 줘.
6. 내 AI Gateway 연결과 모델 접근·비용을 확인하고, 승인된 사용 범위에서 실제 질문을 소량 수집해 줘. 실제 응답과 출처를 저장하고 샘플 데이터를 실측처럼 표시하지 마.
7. Search Console·GA4는 내 Google 계정에서 대상 사이트의 권한을 확인한 뒤 연결해 줘. Google Cloud API, OAuth 클라이언트, APP_URL 기반 복귀 주소, 토큰 암호화, Cron 인증 해시를 설정해 줘. 계정 로그인·OAuth 승인·소유권 검증 등 내 조작이 필요하면 그 단계에서 안내해 줘. 사이트 접근권한이 없으면 다른 사이트 지표로 대신하지 말고 미연결로 남겨 줘.
8. 테스트·빌드·회원 권한 검사를 수행하고 내 Vercel 프로젝트로 배포해 줘. 실제 화면에서 로그인 → 브랜드 등록 → 진단 저장 → AI 응답·경쟁사 근거 → 개선 과제·전략 저장까지 확인해 줘. GA4 태그가 이미 있다면 실제 방문 수신까지 확인하고, 태그 설치나 분석 대상 홈페이지 수정이 필요하면 변경안을 준비한 뒤 별도 승인을 받아 줘.
9. 예약 수집 주기와 질문 수, API 비용·한도를 설명하고 내 운영 조건에 맞춰 설정해 줘. 수동 실행 성공과 미래 예약 실행 검증을 구분해 줘. 아직 관찰하지 않은 예약 실행은 완료라고 쓰지 마.
10. 마지막으로 내 저장소·배포 주소, 완료한 설정, 실제 확인한 데이터, 미완료 항목과 이유, 내가 다음에 눌러야 할 메뉴를 정리해 줘. 내 사본에 설치·운영 문서도 남기되 비밀키·토큰·고객 데이터는 커밋하지 마.

작업 원칙:
- 비밀번호·비밀키를 채팅이나 공개 문서에 요구하거나 출력하지 말고 안전한 환경변수 입력 절차를 이용해 줘.
- 유료 구독·크레딧 구매, 새 데이터 접근권한, 파괴적 변경, 분석 대상 홈페이지 수정·게시가 필요하면 대상과 영향을 설명하고 필요한 승인을 받아 줘.
- 연결되지 않은 서비스나 실패한 측정을 가짜 데이터로 대체하지 마. 계정 연결 성공과 실제 데이터 수신 성공은 각각 확인해 줘.
- 이 앱은 한 팀이 데이터를 공유하는 구조야. 서로 다른 고객을 한 설치 안에서 격리한다고 안내하지 마.
```

진행이 중단되면 같은 대화에서 “지금까지의 설치 상태를 확인하고 남은 단계부터 이어서 진행해 줘”라고 요청하세요. 계정 승인·결제 대기는 완료로 간주하지 않으며, 설치 가이드의 수동 절차로도 이어갈 수 있습니다.

## 먼저 알아둘 것

- **도구 주소**와 **분석 대상 주소**는 다릅니다. 예: 도구 `https://insights.example.com`, 분석 대상 `https://www.example.com`.
- 설치 한 개는 **하나의 팀**을 위한 것입니다. 등록 멤버가 모든 브랜드 데이터를 공유합니다. 고객마다 격리가 필요하면 별도 Supabase 프로젝트와 배포를 사용하세요. 공개 가입형 다중 고객 SaaS가 아닙니다.
- 사이트 진단은 공개 HTTPS 페이지 대상으로 동작합니다. GSC·GA4는 해당 사이트에 접근 권한이 있는 Google 계정이 필요합니다.
- 점수는 자체 체크리스트입니다. Google 순위나 시장 전체 AI 노출률을 뜻하지 않습니다. 미수집·오류를 0점으로 취급하지 않습니다.
- 모델 호출에는 자신의 AI Gateway 사용량과 비용이 발생합니다. 유료 모델·크레딧 구매를 자동으로 진행하지 않습니다.

## 빠른 시작

1. GitHub의 **Use this template** 또는 **Fork**로 본인 저장소를 만듭니다.
2. 본인 저장소를 내려받고 Node.js 24를 준비합니다.
3. 새 Supabase 프로젝트에 `supabase/migrations/`의 SQL 001~008을 순서대로 실행합니다.
4. Supabase Auth에서 이메일·비밀번호 사용자를 만들고 `seo_members`에 해당 사용자 UUID를 등록합니다.
5. 아래 명령으로 실행하고 이메일로 로그인합니다. 자세한 값은 [설치 가이드](docs/SETUP.md)를 따르세요.

```bash
npm ci
cp .env.example .env.local
# .env.local에 자신의 Supabase 주소와 publishable key를 입력
npm run dev
```

6. **브랜드 추가 → 공식 홈페이지·고객·키워드·경쟁사 등록 → 진단 실행**.
7. AI를 사용할 때 AI Gateway를 연결하고, 검색·방문 성과가 필요하면 Google OAuth를 설정합니다.
8. 자신의 Vercel 프로젝트로 배포합니다. 원본 운영 환경이나 다른 사람의 계정을 연결하지 않습니다.

## 제공 기능

| 영역 | 메뉴와 역할 |
|---|---|
| 요약 | 대시보드: 수집 근거와 현재 개선 항목 |
| 검색 분석 | 키워드 현황·키워드 분석: 키워드 관리와 확보된 지표의 비교 |
| AI 분석 | 프롬프트 현황·분석: 질문 생성, 반복 관찰, 경쟁사 언급·출처·인용 구분 |
| 전략 | 전략맵·사이트 진단·개선 과제·4주 실행안 |
| 실행 | 콘텐츠 제작소·최적화·내보내기: 자료 기반 초안, 구조 검사, 파일 출력 |
| 관찰 | 모니터링·주간 리포트: 예약 실행 이력, Google 성과, GA4 실시간 수신 |
| 근거 | 페르소나·자료실·Raw 데이터: 작성 기준, 승인 자료, 응답 원문 |
| 운영 | 브랜드 관리·운영 방법 |

정적 크롤링, Gemini API의 Google 검색 도구, GSC와 GA4를 사용합니다. 소비자용 ChatGPT·Perplexity 화면을 자동 수집하지 않습니다. 별도 SERP 공급자 기반 검색 순위·검색량·Google AI Overview 추적, JS 렌더링 크롤링, Core Web Vitals 측정, 자동 홈페이지 게시·이메일 발송은 제공하지 않습니다.

## 개발·검증

```bash
npm test
npm run build
npm run typecheck
# 선택: 로컬 PostgreSQL의 initdb/pg_ctl/psql이 설치되어 있을 때
bash scripts/check-migrations.sh
```

빌드에도 Supabase 공개 환경변수가 필요합니다. 테스트용 예시 값은 빌드 확인에만 사용할 수 있으며 실제 로그인을 제공하지 않습니다. 로컬 DB 검사는 임시 PostgreSQL에만 연결하고 종료 시 삭제합니다. 원격 DB에 연결하지 않습니다.

Next.js 및 AI SDK API는 설치된 패키지 문서를 먼저 읽습니다. 의존성 버전 재현에는 `package-lock.json`과 `npm ci`를 사용하세요.

공개 저장소 전환은 실행 중인 앱의 데이터를 공개하는 설정이 아닙니다. 앱은 Auth와 RLS를 계속 사용합니다. 환경변수·Google 토큰·운영 데이터를 커밋하지 마세요.
