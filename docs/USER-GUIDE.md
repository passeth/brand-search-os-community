# 내 사이트 분석·개선 운영법

## 첫 30분

1. 설치 관리자가 준비한 이메일·비밀번호로 로그인합니다.
2. **브랜드 추가**에서 내 사이트, 대상 고객, 키워드를 입력합니다. 사이트 URL을 소스 코드에 넣을 필요가 없습니다.
3. **사이트 진단**을 실행합니다. 문제 목록의 URL·검사 근거를 확인하고 우선순위 높은 개선 과제부터 선택합니다.
4. **프롬프트 현황**에서 고객이 실제로 물어볼 질문을 준비합니다. 추천·비교·실행·개념·해결·조건을 섞어 10개 정도로 시작합니다.
5. **프롬프트 분석**에서 경쟁사 명칭과 공식 도메인을 설정합니다. 질문 한 개를 수집해 응답 원문과 출처가 저장되는지 확인합니다.
6. 필요하면 **모니터링 대시보드**에서 Google 계정과 내 사이트의 GSC·GA4를 연결합니다. 설치 설정은 [SETUP.md](SETUP.md)를 참고합니다.

여러 사이트가 있으면 브랜드를 각각 추가합니다. 작업 전 상단 선택이 어느 사이트인지 확인하세요. 한 설치의 모든 팀원은 모든 브랜드를 함께 봅니다.

## 질문 설계와 경쟁사 비교

예시 업종이 소프트웨어라면 “소규모 팀에 적합한 일정 관리 서비스는?”처럼 브랜드명을 넣지 않은 발견 질문과 “샘플 서비스와 비교 서비스의 차이는?” 같은 브랜드 포함 질문을 구분하세요. 브랜드명을 질문에 직접 넣고 답변에 나왔다는 이유로 시장 인지도가 높다고 해석하면 안 됩니다.

경쟁사는 같은 고객의 문제를 해결하는 2~3곳부터 시작합니다. 공식 도메인을 함께 등록해야 출처가 정말 그 회사 사이트인지 판단할 수 있습니다. 답변에 이름이 나오는 **언급**, 제공자 메타데이터의 **출처**, 특정 주장에 연결된 **인용**은 다른 지표입니다. URL이 해석되지 않거나 인용 메타데이터가 없으면 미확인으로 봅니다.

## 메뉴 사용 순서

| 메뉴 | 무엇을 하고 다음에 어디로 가나요? |
|---|---|
| 대시보드 | 현재 근거와 문제 확인 → 상세 분석 |
| 키워드 현황 | 사이트와 고객에 맞는 키워드 정리 → 키워드 분석 |
| 키워드 분석 | 확보된 지표와 누락 확인 → 전략맵 |
| 프롬프트 현황 | 질문 등록·생성·활성화 → 수집 |
| 프롬프트 분석 | 원문·경쟁사·출처 비교 → 개선 과제 |
| 전략맵 | 검색·AI에서 약한 주제 찾기 → 콘텐츠 계획 |
| 사이트 진단 | 공개 페이지 기술/구조 검사 → 문제 URL 수정 |
| 콘텐츠 제작소 | 승인 자료를 바탕으로 초안 작성 → 검토 |
| 콘텐츠 최적화 | URL/텍스트 구조 검사 → 수정안 검토 |
| 콘텐츠 내보내기 | 승인할 초안을 파일로 출력 → 홈페이지 담당자 전달 |
| 모니터링 대시보드 | Google 연결·예약·실행 상태 확인 |
| 주간 리포트 | 같은 질문의 전후 변화 확인 → 다음 주 우선순위 |
| 페르소나 | 작성자 역할·문체·규칙 등록 |
| 자료실 | 확인된 제품/서비스 사실과 근거 등록 |
| Raw 데이터 | 원문·출처·실행 시점 확인 |
| 브랜드 관리 | 사이트·고객·키워드·비교 대상 수정 |
| 개선 과제 | 할 일·진행·완료 상태 관리 |
| 4주 실행안 | 수집 근거 기반 일정·할 일 정리 |
| 운영 방법 | 측정 해석과 운영 순서 다시 보기 |

## 개선 전략 만들기

1. 비교사가 언급되는 질문 중 우리 사이트에 답변이 부족한 주제를 고릅니다.
2. 기존 페이지에서 그 질문의 답, 적용 조건, 한계, 사실 근거가 있는지 확인합니다.
3. 자료실에 검증된 근거를 넣고 초안을 만듭니다. 기능·성능·가격·인증을 AI가 추정한 내용은 승인하지 않습니다.
4. 제목, 첫 문단의 직접 답변, 표·목록·FAQ, 담당자와 갱신일을 보완합니다.
5. 게시 승인 후 홈페이지 관리자가 실제 사이트에 적용합니다. 이 앱은 자동 게시하지 않습니다.
6. 같은 질문과 비교군으로 재측정합니다. 질문·모델·프로토콜·비교군을 바꾸면 단순 전후 비교가 아닙니다.

## 매주 반복

- 월요일: 수집 실패 여부, 사이트 문제, 약한 질문 확인. 이번 주 과제 1~3개 결정.
- 화~목: 근거 보강, 콘텐츠 검토, 실제 홈페이지 수정.
- 금요일: 동일 질문 재수집 결과와 검색·방문 성과 확인. 표본과 처리 지연을 기록.

자동 수집을 켜도 반드시 실행 기록을 확인합니다. 수집 실패는 “언급 없음”이 아닙니다. 실시간 GA4 값은 최근 30분 확인용이며 일별 데이터에 합산하지 않습니다. 점검용 방문도 포함됩니다.

## 해석 한계

Google 순위·검색량 공급자는 기본 연결돼 있지 않습니다. AI 결과는 설정한 모델/API/질문의 관찰값이고 전체 소비자 검색 경험을 대표하지 않습니다. 정적 사이트 진단은 JS 렌더링 브라우저 검사나 실제 사용자 속도 측정을 대신하지 않습니다. 초안은 사실 검증과 게시 승인 전까지 초안입니다.
